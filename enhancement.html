CS 340 Enhancement: Analytics & Performance

Compound Indexes, Aggregation Pipelines, and Secure Credential Handling

Enhancement Overview

Building upon the solid foundation of Project Two, this enhancement transforms the Animal Shelter system by adding performance-optimized database indexes, MongoDB aggregation pipelines for data analytics, and improved security practices in the dashboard. The enhancement demonstrates professional database design patterns and scalable data analysis techniques.

Technology Stack: Python, MongoDB, PyMongo, Plotly Dash, Pandas

New Concepts: Compound Indexes, Aggregation Pipelines, Data Mining, Secure Credential Input

What Changed?

The enhancement adds new capabilities while preserving all original functionality:

Before (Project Two)

  • Basic CRUD operations with no index optimization
  • Hardcoded credentials in the notebook
  • No analytical or aggregation capabilities
  • Read method accepted None as query (could cause issues)

After (Enhancement)

  • Compound indexes on frequently queried fields for faster lookups
  • Runtime credential prompting in the dashboard for improved security
  • Three aggregation pipeline methods for trend analysis and reporting
  • Read method defaults to empty query {} for safer behavior
  • Comprehensive module-level docstring documenting all enhancements

Performance Enhancements: Compound Indexes

The enhanced module automatically creates two compound indexes on startup to accelerate the most common query patterns:

Index 1: Animal Breed Age Index

self.collection.create_index(
    [
        ("animal_type", ASCENDING),
        ("breed", ASCENDING),
        ("age", ASCENDING)
    ],
    name="animal_breed_age_idx"
)

This index dramatically speeds up the rescue type filter queries used by the dashboard, which filter by animal_type, breed, and age_upon_outcome_in_weeks.

Index 2: Intake Condition Index

self.collection.create_index(
    [
        ("intake_condition", ASCENDING),
        ("animal_type", ASCENDING)
    ],
    name="intake_condition_idx"
)

This index supports the intake_condition_analysis() aggregation pipeline, which groups animals by intake condition.

Index Initialization

def __init__(self, user, pwd):
    # ... connection setup ...
    self._create_indexes()  # Called automatically on every instantiation

Indexes are created safely via create_index(), which is idempotent—calling it multiple times with the same parameters has no negative effect.

Data Analytics: Aggregation Pipelines

Three new analytical methods use MongoDB's aggregation framework to support data mining and trend analysis without loading all records into Python memory:

1. Adoption Trends by Breed

def adoption_trends_by_breed(self, animal_type):
    pipeline = [
        {"$match": {"animal_type": animal_type}},
        {"$group": {"_id": "$breed", "count": {"$sum": 1}}},
        {"$sort": {"count": -1}}
    ]
    return list(self.collection.aggregate(pipeline))

Returns a ranked list of breeds by frequency for a given animal type. Useful for identifying which breeds are most commonly available for rescue training.

2. Adoption Trends by Age

def adoption_trends_by_age(self, animal_type):
    pipeline = [
        {"$match": {"animal_type": animal_type}},
        {"$group": {"_id": "$age", "count": {"$sum": 1}}},
        {"$sort": {"_id": 1}}
    ]
    return list(self.collection.aggregate(pipeline))

Groups animals by age and returns frequency counts in ascending order. Supports age distribution analysis for a given animal type.

3. Intake Condition Analysis

def intake_condition_analysis(self):
    pipeline = [
        {"$group": {"_id": "$intake_condition", "count": {"$sum": 1}}},
        {"$sort": {"count": -1}}
    ]
    return list(self.collection.aggregate(pipeline))

Analyzes intake conditions across all animals and returns a ranked summary. Helps identify patterns in how animals arrive at the shelter.

Security Improvement: Credential Handling

One of the most impactful changes in the enhanced dashboard is the removal of hardcoded credentials:

Before (Original Dashboard)

# Hardcoded credentials visible in source
username = 'aacuser'
password = 'JeyAndMax2025'
db = AnimalShelter(username, password)

After (Enhanced Dashboard)

# Credentials prompted at runtime — never stored in source
username = input("Enter username: ")
password = input("Enter password: ")
db = AnimalShelter(username, password)

This change ensures that credentials are never committed to version control, reducing the risk of accidental credential exposure in public repositories.

Scalability Improvements

The enhancements are specifically designed to support larger datasets:

  • Server-Side Analytics: Aggregation pipelines run on the MongoDB server, reducing network transfer and Python memory usage
  • Index-Accelerated Queries: Compound indexes prevent full collection scans as the dataset grows
  • Idempotent Index Creation: _create_indexes() is safe to call repeatedly, enabling use across multiple application instances
  • Modular Analytics: Each analytical method is independent, making it easy to add new pipeline methods without modifying existing code

Enhancement Narrative

This enhancement demonstrates the evolution from a functional prototype to a performance-aware, analytics-capable application. The transformation showcases several important software engineering skills:

Database Performance Design

Adding compound indexes shows an understanding of database internals and query optimization. By analyzing which fields are most commonly used in filter queries, I identified the optimal index structure to minimize query execution time as the dataset grows.

Data Mining with Aggregation Pipelines

Implementing MongoDB aggregation pipelines demonstrates the ability to leverage database-native capabilities for analytics. Rather than loading all records into Python and computing statistics with Pandas, the enhanced module delegates computation to MongoDB—a more scalable and efficient approach.

Security Awareness

Replacing hardcoded credentials with runtime input demonstrates awareness of secure coding practices. Credentials embedded in source files are a common security vulnerability, especially in academic projects that may be shared publicly.

Backward Compatibility

The enhancement preserves all original CRUD functionality while adding new capabilities. All existing dashboard features continue to work unchanged. This demonstrates the ability to extend a system without breaking existing behavior—a critical skill in professional software development.
