Project Two: Animal Shelter Dashboard

Original Implementation with MongoDB CRUD Module and Plotly Dash Dashboard

Overview

Project Two is a full-stack client/server application for Grazioso Salvare, an international rescue-animal training company. The project connects a Python CRUD module to a MongoDB database and exposes the data through an interactive Plotly Dash web dashboard.

Technology Stack: Python, MongoDB, PyMongo, Plotly Dash, Pandas

Key Concepts: CRUD Operations, MVC Pattern, Data Filtering, Interactive Visualizations

GitHub: View Source Code

System Components

The system is composed of two primary components that follow the Model-View-Controller (MVC) pattern:

1. CRUD Python Module (CRUD_Python_Module.py)

The AnimalShelter class encapsulates all database operations for the animals collection in MongoDB:

  • create(data): Inserts a new document and automatically assigns the next available record number if not provided
  • read(query): Queries documents matching a filter; returns all documents when no filter is provided
  • update(query, values): Updates all documents matching the query using $set; returns the count of modified documents
  • delete(query): Deletes all documents matching the query; returns the count of deleted documents
  • get_next_record_number(): Helper method to auto-increment record numbers using a descending sort

2. Dashboard (ProjectTwoDashboard.ipynb)

The Jupyter Dash dashboard provides an interactive interface for browsing and filtering animal data:

  • Grazioso Salvare Logo: Branding element displayed at the top of the dashboard
  • Rescue Type Filter: Radio buttons to filter by All, Water Rescue, Mountain Rescue, or Disaster Rescue
  • Interactive Data Table: Paginated, sortable, and filterable table with single-row selection
  • Breed Pie Chart: Displays the top 5 breeds from the currently visible data
  • Geolocation Map: Centers on the coordinates of the selected row using Dash Leaflet

CRUD Module Code

Class Initialization

class AnimalShelter(object):
    """CRUD operations for Animal collection in MongoDB"""

    def __init__(self, user, pwd):
        HOST = 'localhost'
        PORT = 27017
        DB = 'aac'
        COL = 'animals'
        self.client = MongoClient(
            f'mongodb://{user}:{pwd}@{HOST}:{PORT}/?authSource={DB}'
        )
        self.database = self.client[DB]
        self.collection = self.database[COL]

Create Operation

def create(self, data):
    if not data:
        raise ValueError("Nothing to save; 'data' parameter is empty")
    if "rec_num" not in data:
        data["rec_num"] = self.get_next_record_number()
    try:
        result = self.collection.insert_one(data)
        return result.acknowledged
    except PyMongoError as e:
        print(f"Insert failed: {e}")
        return False

Read Operation

def read(self, query=None):
    try:
        return list(self.collection.find(query))
    except PyMongoError as e:
        print(f"Query failed: {e}")
        return []

Dashboard Architecture

The dashboard follows the MVC pattern by separating data access, layout, and interaction logic:

┌──────────────────────────────────────┐ │ View Layer (Layout) │ │ Logo, Title, Radio Buttons │ │ Data Table, Pie Chart, Map │ └──────────────────────────────────────┘ ↓ ┌──────────────────────────────────────┐ │ Controller Layer (Callbacks) │ │ update_dashboard() → filter data │ │ update_graphs() → update chart │ │ update_map() → update map │ │ update_styles() → highlight col │ └──────────────────────────────────────┘ ↓ ┌──────────────────────────────────────┐ │ Model Layer (CRUD Module) │ │ AnimalShelter.read(query) │ │ MongoDB animals collection │ └──────────────────────────────────────┘

Key Features

  • Modular Design: CRUD operations are fully separated from the dashboard UI
  • Auto-Incrementing Records: New documents are automatically assigned sequential record numbers
  • Interactive Filtering: Real-time data filtering via radio buttons without page reload
  • Single-Row Selection: Clicking a table row updates both the pie chart and the map
  • Geolocation Map: Displays the precise location of the selected animal using Dash Leaflet
  • Error Handling: All database operations catch PyMongoError and return safe fallback values

Lessons Learned

This project reinforced several important software engineering principles:

  • Separation of Concerns: Keeping the CRUD module separate from the dashboard makes each component easier to maintain and test independently
  • MVC Pattern: Structuring the application into Model (CRUD/MongoDB), View (layout), and Controller (callbacks) improves organization
  • Error Handling: Wrapping database calls in try/except blocks prevents application crashes and provides meaningful feedback
  • Reactive UI: Dash callbacks enable a fully reactive interface where every component responds to user interactions without page reloads
